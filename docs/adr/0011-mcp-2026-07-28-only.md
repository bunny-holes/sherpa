# Sherpa MCP 서버는 2026-07-28 규격만 받는다

상태: 채택(소유자 결정, 2026-11-22, bunny-holes/sherpa#51). [ADR-0010](0010-menu-bar-app-and-mcp.md) 의 서버 구조(앱 안 Bun
코어 하나, 채널마다 `serveStdio`, Swift 중계)는 그대로다. 이 결정이 대체하는 것은 ADR-0010 실측 표의 "협상 규격
2025-11-25" 와, [앱 연결 계약](../contracts/app-connection-v1.md) §10.1 이 2025-11-25 를 보증하고 SDK 기본값으로 두
세대를 함께 받던 것이다.

## 맥락

- 코어는 SDK 2.4.0 `serveStdio` 의 기본값(`legacy: 'serve'`)으로 `initialize` 로 여는 2025 계열과 요청마다 봉투를
  다는 2026-07-28 을 모두 받았다.
- 그 보증의 근거였던 "Claude Code 2.1.326 과 Codex 0.170.0 이 2025-11-25 로 협상했다" 는 에이전트가 아니라 손으로
  보낸 `initialize` 로 서버를 잰 값이었다(실측 기록 2026-11-22 정정).
- 2026-07-28 은 `initialize` 와 프로토콜 세션을 없앴다. 요청마다 `_meta` 에 규격(`io.modelcontextprotocol/protocolVersion`)과
  클라이언트 능력을 반드시 싣고, 클라이언트 정보(`clientInfo`)도 싣는 것이 권고(SHOULD)다. 서버는 같은 연결의 앞선
  요청으로 능력·규격·클라이언트 신원을 세우면 안 된다. [문서: MCP 2026-07-28 [changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog),
  [Overview](https://modelcontextprotocol.io/specification/2026-07-28/basic) "Statelessness"]
- 확인 기록의 `client` 를 `initialize` 의 `clientInfo`(`getClientVersion()`)에서 읽던 코어는 2026-07-28 연결에서 값이
  없어 `unknown` 을 적었다. SDK 는 그 접근자를 폐기 예정으로 두고 요청의 `ctx.mcpReq.envelope` 를 읽게 한다. [문서:
  SDK 2.4.0 `Server.getClientVersion` 의 `@deprecated`]

## 결정

1. 코어는 2026-07-28 만 받는다. 채널마다 `serveStdio(factory, { transport, legacy: "reject" })` 를 돌린다. 2025 계열
   열기(`initialize`, 봉투 없는 요청)는 받지 않는다. 기본 설정의 Codex 0.171.0 이 붙지 못하는 것을 받아들인다.
   [소유자]
2. 확인 기록의 `client` 는 그 호출의 요청 봉투 `io.modelcontextprotocol/clientInfo` 에서 읽는다. 자기 신고 값이고,
   봉투에 없으면 이름과 버전이 `unknown` 이다. 같은 연결의 다른 요청 값을 옮기지 않는다. [소유자 결정 1 에서
   끌어냄; 계약 §9]
3. 삭제·보내기의 매 호출 확인은 앱 창 그대로다(계약 §9). 두 에이전트가 2026-07-28 에서 elicitation 을 선언해도
   바꾸지 않는다. 근거는 "결과" 에 적는다. [소유자]

## 거부의 모양

| 받은 것 | 답 |
| --- | --- |
| 봉투 없는 `initialize`(`protocolVersion` 이 X) | `-32022`, message `Unsupported protocol version: X`, data `{"supported":["2026-07-28"],"requested":"X"}` |
| 연결이 2026-07-28 로 열리기 전, 봉투 없는 다른 요청 | `-32022`, message `Unsupported protocol version: the request did not name a protocol version`, data `{"supported":["2026-07-28"]}` |
| 봉투 없는 알림(`notifications/initialized` 등) | 답 없이 버린다 |
| 2026-07-28 로 열린 뒤 봉투 없는 요청 | `-32602`, message `Request is missing the required _meta envelope for protocol revision 2026-07-28 (…)` |
| 2026-07-28 로 열린 뒤 봉투 없는 `initialize` | 첫 줄과 같은 `-32022` |

- 거부해도 연결은 닫히지 않는다. 같은 연결에 `server/discover` 나 봉투를 단 요청이 오면 2026-07-28 로 연다. [문서:
  `@modelcontextprotocol/server` 2.4.0 `dist/stdio.mjs` 의 `serveStdio`·`answerLegacyRejection`, `dist/src-*.mjs` 의
  `modernOnlyStrictRejection`·`checkInboundEnvelope`; 실측: `core/tests/app-serve.test.ts`, `core/tests/stdio/serve.test.ts`]
- 규격은 지원하지 않는 판을 요청받은 서버가 지원 목록을 단 `UnsupportedProtocolVersionError`(-32022)로 답하게 하고,
  필수 봉투 키가 없는 요청을 -32602 로 거부하게 한다. [문서: MCP 2026-07-28
  [Versioning](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning) "Protocol Version
  Negotiation", Overview `_meta` "Per-request protocol fields"]
- 코어는 -32022 로 답할 때마다 `warn [core:mcp-transport:send] refused channel=N reason=unsupported_protocol_version`
  을 남긴다. 2025 계열 에이전트가 붙으려 했다는 것을 앱의 통합 로그에서 찾게 하려는 것이다. [계약]

## 에이전트 조건

- **Claude Code:** stdio 서버에 기본으로 2026-07-28 을 묻는다. [문서: [Claude Code MCP](https://code.claude.com/docs/en/mcp),
  "Push messages with channels": "Claude Code asks stdio servers for that revision by default."] 2.1.326 은
  `sherpa-relay` 를 거친 시험 서버와 2026-07-28 로 협상했다(클라이언트 로그 `negotiatedProtocolVersion`). [실측: 실측
  기록 2026-11-22] 이 결정의 코어를 담은 내보낸 앱에도 `server/discover` 로 2026-07-28 로 붙어 도구 목록을 받았다.
  [실측: 같은 기록] `main` `8de36c6` 을 처음부터 빌드해 내보낸 앱에서는 `claude -p` 로 도구 호출까지 했다. [실측: 실측
  기록 2026-11-22 "Claude Code calls a tool"]
- **Codex 0.171.0:** 기본은 `initialize`(2025-06-18)라 거부되고, 더 새 판으로 다시 묻지 않는다. stdio 서버에 2026-07-28 로 붙으려면 둘 다 있어야
  하고, 하나라도 없으면 2025-06-18 로 연다. [문서: openai/codex `rust-v0.171.0`
  `codex-rs/rmcp-client/src/protocol_mode.rs` 의 `stdio_mode` 와 시험
  `stdio_requires_both_the_modern_feature_and_a_server_opt_in`; 실측: 실측 기록 2026-11-22]
  1. 기능 `mcp_2026_07_28` 을 켠다(`codex features enable mcp_2026_07_28`, 또는 실행마다 `--enable mcp_2026_07_28`).
     단계는 `UnderDevelopment`, 기본 꺼짐이다. [문서: `codex-rs/features/src/lib.rs`]
  2. 서버 항목의 env 에 `CODEX_MCP_PROTOCOL_VERSION = "2026-07-28"` 을 둔다. Codex 는 이 값을 프로세스 환경이 아니라
     서버 항목의 env 에서 읽고, 2026 모드에서는 서버를 띄우기 전에 지운다. [문서: `codex-rs/codex-mcp/src/server.rs`
     108–116, `codex-rs/rmcp-client/src/rmcp_client.rs` 522–528] 기능이 꺼져 있으면 지우지 않고 중계에 넘긴다. 릴리스
     중계는 환경 변수를 읽지 않으므로 아무 일도 없다. [추론; 계약 §2]

```toml
[mcp_servers.sherpa]
command = "/Applications/Sherpa.app/Contents/MacOS/sherpa-relay"
env = { CODEX_MCP_PROTOCOL_VERSION = "2026-07-28" }
```

## 위험

- Claude Code 가 2026-07-28 을 묻지 않으면 2025-11-25 `initialize` 로 붙고, 거부돼 연결이 실패한다. 문서가 적은
  경우는 둘이다. [문서: Claude Code MCP, "MCP client runtimes"]
  - "Anthropic can keep a specific server on the earlier protocol, or off that stream, with a feature flag Claude Code
    fetches."
  - "With that variable unset, Claude Code can skip asking a stdio server for 7 days, for example after the server
    exits when asked. To have an upgraded server asked sooner, set `auto`." (변수는 `MCP_PROTOCOL_NEGOTIATION`)
- MCP 가 꺼진 앱에서 중계가 머리말을 읽고 끝나면 Claude Code 2.1.326 대화형은 그 시도 안에서 서버를 옛 규격으로
  고정해 다시 띄운다(`respawning pinned legacy`). 다시 띄운 중계도 같은 이유로 끝나 그 시도는 실패한다. [실측: 실측
  기록 2026-11-22 "Claude Code against a relay turned away"]
  - `--mcp-config` 동적 서버에서는 고정이 다음 세션에 남지 않았다. 2초 뒤 세션은 실패 캐시 없이 다시 시도해 같은
    이유로 실패했고, MCP 를 켠 뒤 세션은 2026-07-28(`protocolEra` `modern`)로 붙었다. [실측: 같은 기록]
  - 사용자 범위와 플러그인 범위에서 고정이 남는지는 재지 않았다. [미확인] 남는다면 MCP 를 켠 뒤에도 그 서버는
    2025-11-25 `initialize` 로 붙어 거부된다. [추론]
  - 그래서 중계와 앱은 어느 경우에도 맞는 다시 붙는 법(Claude Code 는 `/mcp` 의 Reconnect)을 적는다(계약 §6).
- 앱이 떠 있지 않으면 중계는 머리말 전에 69 로 끝난다(계약 §6). Claude Code 가 그때 물었다면 7일 생략에 걸릴 수
  있다. [추론, 재현 안 함] 머리말 단계에서 끝난 위의 경우는 동적 서버에서 7일 생략으로 이어지지 않았다. 69 는 재지
  않았다. 그때는 Claude Code 환경에 `MCP_PROTOCOL_NEGOTIATION=auto` 를 둔다. 그 변수가 `legacy` 거나
  `MCP_SDK_GENERATION=v1` 이면 붙지 못한다. [문서: 같은 절]
- Codex 의 2026 모드는 2026-07-28 을 먼저 시도하고 2025-06-18 을 예비로 둔다(`ClientLifecycleMode::Auto`). [문서:
  `protocol_mode.rs`] 예비로 내려가면 거부된다. 내려가는 조건은 Codex 가 쓰는 rmcp 소스를 읽지 않아 모른다.
  [미확인]
- SDK 의 `SUPPORTED_MODERN_PROTOCOL_VERSIONS` 는 `["2026-07-28"]` 하나다. 새 판만 묻는 에이전트도 -32022 를 받는다.
  SDK 를 올릴 때 이 목록과 계약 §10.1 을 함께 본다. [문서: SDK 2.4.0 `protocolEras`; 추론]

## 결과

- 시험과 스모크는 `server/discover` 와 봉투를 단 요청으로 연다. 2025-11-25·2025-06-18 `initialize` 의 거부, 봉투 없는
  요청의 거부, 거부 뒤 같은 연결의 2026-07-28 열기, 요청마다 봉투에서 오는 확인 기록의 `client` 를 코어의 단위
  시험과 빌드한 코어의 stdio 시험이 회귀로 본다.
- 확인 창의 `client` 는 그 호출이 자기 봉투에 적은 값이다. 같은 연결에서도 요청마다 다를 수 있다.
- 앱 창 확인을 유지하는 근거: 2026-07-28 에서 elicitation 은 서버가 보내는 요청이 아니라 도구 결과로 입력을 되묻는
  방식(Multi Round-Trip Requests)이다. [문서: changelog] Claude Code 는 2026-07-28 연결마다
  `elicitation: {form: {}, url: {}}` 를 선언한다. [문서: Claude Code MCP, "Elicitation modes Claude Code declares"]
  Codex 0.171.0 도 form 과 url 을 선언한다. 그러나 승인 정책이 `never` 면 샌드박스에서는 거절하고, 전체 접근이면
  필드 없는 폼을 사람 없이 `{}` 로 수락한다. 검토자가 `auto_review` 면 사람 대신 검토 모델이 정한다. [문서:
  `codex-rs/core/src/config/mod.rs` 2051–2059, `codex-rs/codex-mcp/src/elicitation.rs` 569–580·605–611·718–726,
  `codex-rs/ext/guardian-reviewer/src/elicitation.rs`] 답이 에이전트 설정에 따라 사람 없이 나올 수 있으므로 확인은
  모델과 에이전트를 거치지 않는 앱 창에 둔다.
- 플러그인이 MCP 설정을 등록하는 일은 bunny-holes/sherpa#55 가 했다. 플러그인의 `.mcp.json` 이 Codex 항목에 위 env 를
  넣고, 플러그인 README 가 기능 `mcp_2026_07_28` 을 켜는 명령을 안내한다(계약 §2 "플러그인의 MCP 등록").

## 아직 확인 전

- Claude Code 의 7일 생략과 기능 플래그가 이 Mac 에서 일어나는지. 2026-11-22 `--mcp-config` 동적 서버에서는 머리말
  단계에서 끝난 중계 뒤에도 일어나지 않았다.
- 사용자 범위와 플러그인 범위의 Claude Code 서버에서 옛 규격 고정이나 실패 캐시가 다음 세션에 남는지. 플러그인
  범위는 2026-11-22 에 일부를 쟀다. 소켓이 없어 중계가 69 로 끝나자 Claude Code 는 그 시도 안에서 probe 없이
  `initialize`(2025-11-25)로 한 번 다시 띄웠다. 15분 안의 새 세션은 실패 캐시로 서버를 띄우지 않았다. 서버 항목을
  바꾼 뒤의 새 세션은 다시 `server/discover` 부터 물었다. 항목이 같은 채로 15분 뒤에 고정이 남는지는 재지 않았다.
  [실측: 실측 기록 2026-11-22 "The plugin's `.mcp.json`"]

내보낸 앱 경로로 Claude Code 가 도구를 부르는지는 2026-11-22 `main` `8de36c6` 빌드로 확인했다(위 "실측").

## 검토한 대안

- **두 세대를 함께 받기(SDK 기본값):** 기본 설정 Codex 가 붙는다. 그러나 2025 쪽은 `initialize` 로 세운 연결 상태에
  기대는 다른 경로라 시험·확인 기록·문서가 두 모양을 따라야 하고, SDK 도 그 쪽을 레거시로 둔다. 소유자는 2026-07-28
  만 받기로 했다.
- **2025-11-25 만 받기:** Claude Code 의 기본(2026-07-28)과 어긋나고, 규격이 없앤 세션에 기댄다.
